## 1. 诞生背景与行业痛点 (Why Now?)

在数字内容爆发的今天，全球图形学领域正面临着巨大的“断层”：

* **传统离线渲染太慢**：影视动画行业长期依赖 Arnold/V-Ray 等离线渲染器，画质虽好，但单帧渲染耗时数小时，严重制约了创作者的迭代效率。
* **主流游戏引擎太重**：Unreal Engine (UE) 和 Unity 虽然实现了实时渲染，但它们本质上是为“游戏逻辑”设计的。对于纯粹追求画质的影视、广告和数字艺术行业来说，它们充满了冗余的代码（Legacy Code）、复杂的编译流程和庞大的资产包袱。
* **AI 与 3D 的割裂**：目前的 AIGC（生成式 AI）大多停留在 2D 平面，缺乏与 3D 深度工作流的底层结合。

**Limx Engine 应运而生。** 我们不是要做另一个游戏引擎，我们要打造的是**“实时时代的数字暗房”**——一个轻量级、极致画质、原生 AI 的视觉生产平台。

## 2. 产品定义 (Product Definition)

**Limx Engine** 是一款基于 **C++ 和 Vulkan** 架构构建的**次世代实时渲染引擎**。

它专注于**“视觉（Visuals）”**而非“玩法（Gameplay）”。它像手术刀一样精准切入高端美术市场，旨在消除“实时渲染”与“电影级画质”之间的最后一道界限，让艺术家在毫秒级的时间内，获得好莱坞级别的光影反馈。

* **核心定位**：美术级 · 影视导向 · AI 原生
* **技术基座**：Modern C++ & Vulkan High-Performance Core
* **开源属性**：打破国外商业引擎的技术黑盒，建立中国自己的高端图形学生态。

## 3. 核心竞争力 (Key Pillars)

### ① 极致的“美术级”表现 (Uncompromised Fidelity)
Limx 拒绝妥协。我们重写了渲染管线，只为追求光影的**物理正确性**。
* **真·光线追踪**：摒弃传统游戏引擎的模拟光照技巧（Rasterization hacks），Limx 以**混合光线追踪（Hybrid Ray Tracing）**为核心，实时呈现物理级准确的反射、折射、软阴影和全局光照（GI）。
* **材质的触感**：原生支持影视级材质标准（MaterialX），无论是皮肤的通透感、金属的氧化层，还是布料的丝绒感，都能 1:1 还原真实世界的质感。

### ② 它是画笔，不是代码 (Artist-First Workflow)
传统引擎要求艺术家像程序员一样思考（编译 Shader、优化 Draw Call）。Limx 改变了这一切。
* **所见即所得**：极简的 UI 设计，让操作逻辑更接近摄影机和调色盘，而非 IDE 代码编辑器。
* **无缝兼容**：直接支持 USD（皮克斯通用场景描述）工业标准，无缝对接 Maya、Houdini、Blender 等主流 DCC 软件，无需繁琐的资产转入转出。

### ③ 次世代 AI 引擎 (Neural Core)
Limx 是全球首批将 **AI (神经网络)** 植入渲染底层的引擎之一。
* **AIGC 资产生成**：内置生成式 AI 接口。美术师只需输入文字（Prompt），即可在 3D 场景中实时生成 PBR 贴图、环境贴图甚至 3D 模型资产。
* **神经渲染 (Neural Rendering)**：利用 AI 预测光线路径，将光追渲染速度提升数倍；支持 **3D Gaussian Splatting（高斯泼溅）** 技术，允许直接将无人机拍摄的现实场景瞬间转化为可编辑的 3D 场景。

### ④ Vulkan 极致性能 (Limitless Performance)
得益于底层采用先进的 **Vulkan** API 和无历史包袱的 **C++** 架构：
* **超大场景承载力**：支持**影视级资产（无需拓扑优化/无需低模）**的亿级面数直接渲染，美术师可直接使用 ZBrush/扫描模型。
* **跨平台算力榨取**：深度优化 GPU 调度，让国产硬件也能跑出顶级画质。

### 4.2 核心技术验证状态

#### ① VisBuffer + Virtual Cluster Geometry

| 项目 | 说明 |
|------|------|
| **技术原理** | 将几何体切分为 Cluster，GPU 驱动剔除，仅渲染可见像素 |
| **业界验证** | UE5 Nanite 已在《黑客帝国觉醒》等项目中验证 |
| **学术基础** | "Visibility Buffer Rendering" (Wihlidal, 2013)、"GPU-Driven Rendering Pipelines" (Ubisoft, 2015) |
| **Limx 方案** | 参考 Nanite 架构，结合 Vulkan Mesh Shader 实现 |
| **预期性能** | **条件性声明**：标准测试场景（1 亿三角形、无透明、4K）+ RTX 4080 + 驱动 550+，目标 **45-60 fps**；中端（RTX 3060）目标 **25-35 fps** |
| **回退方案** | 若性能不达预期，回退至传统 Deferred + LOD 混合模式 |
| **参考基准** | UE5 Nanite: 数十亿三角形 @ 30fps (RTX 3080)¹ |

> ¹ Epic Games, "Nanite Technical Overview", GDC 2021

#### ② 混合光线追踪 + ReSTIR

| 项目 | 说明 |
|------|------|
| **技术原理** | 光栅化主视图 + 光追反射/阴影/GI，ReSTIR 重采样降噪 |
| **业界验证** | Cyberpunk 2077、Alan Wake 2、Path of Exile 2 |
| **学术基础** | "ReSTIR DI" (SIGGRAPH 2020)、"ReSTIR GI" (2021) |
| **Limx 方案** | Vulkan Ray Tracing + 自研 ReSTIR 实现 |
| **预期性能** | **条件性声明**：1,000-10,000 动态光源 + RTX 4080 + 1080p，目标 **<16ms/帧**（含降噪）；极端场景（50,000+ 光源）需降级 |
| **回退方案** | 若 ReSTIR 不稳定，回退至 Tiled Deferred + 时域滤波 |
| **里程碑** | M1 阶段完成基础实现，M2 阶段性能优化 |

#### ③ 光谱渲染管线

| 项目 | 说明 |
|------|------|
| **技术原理** | 使用光谱采样替代 RGB，物理准确模拟色散、薄膜干涉、荧光 |
| **业界验证** | Weta Digital（阿凡达）、Manuka 渲染器 |
| **学术基础** | "Spectral Rendering with Bounded MESE" (2024) |
| **Limx 方案** | Hero Wavelength Spectral Sampling + ACES 输出 |
| **预期性能** | **条件性声明**：8 波长采样 + 简单材质，开销 **+10-20%**；复杂材质（SSS、薄膜）可达 **+30-50%** |
| **回退方案** | RGB 快速模式为默认，光谱模式为可选高质量输出 |
| **里程碑** | M2 阶段完成，作为 Pro 版差异化功能 |

#### ④ Neural Radiance Cache (NRC)

| 项目 | 说明 |
|------|------|
| **技术原理** | 用神经网络缓存间接光照，替代传统 Irradiance Probe |
| **业界验证** | NVIDIA RTXGI 2.0、学术原型 |
| **学术基础** | "Real-time Neural Radiance Caching" (SIGGRAPH 2021) |
| **Limx 方案** | 轻量级 MLP + Vulkan Compute 推理 |
| **预期性能** | **条件性声明**：轻量 MLP（128-256 神经元）+ FP16 + RTX 4080，目标 **1-3ms/帧**；未优化版本 5-8ms |
| **回退方案** | 若 NRC 不稳定，回退至 Irradiance Probe + Screen-Space GI |
| **里程碑** | M2 阶段完成原型，M3 阶段生产就绪 |

#### ⑤ USD Hydra 集成

| 项目 | 说明 |
|------|------|
| **技术原理** | 实现 Hydra Render Delegate，接入 USD 生态 |
| **业界验证** | Pixar、NVIDIA Omniverse、Blender 3.x |
| **开源基础** | OpenUSD (Apache 2.0)、Hydra API |
| **Limx 方案** | 实现 HdRenderDelegate 接口 |

### 4.3 技术栈选型依据

| 选型 | 选择 | 理由 | 替代方案 |
|------|------|------|----------|
| **语言** | C++23 | 零开销抽象、编译时计算、模块化 | Rust（生态不足） |
| **图形 API** | Vulkan 1.4 | 跨平台、显式控制、光追支持 | DX12（仅 Windows） |
| **标准库** | 自研 | 零 STL 依赖，极致性能控制 | STL（性能不可控） |
| **场景格式** | USD | 行业标准、Hydra 生态 | glTF（功能不足） |
| **AI 推理** | Vulkan Compute | 无额外依赖、跨平台 | CUDA（仅 NVIDIA） |

#### 实测性能（NVIDIA RTX 3060 / 1280×720 / Vulkan 1.4）

**综合场景**（35 个物体，三种光源类型都投影，全套后处理）：

| 指标 | 数值 |
|------|------|
| 帧时间 | **1.19 ms** (839 fps) |
| CPU 合计 | 1.18 ms（其中命令录制 0.60 ms） |
| GPU 整帧 | 1.07 ms |
| 显存占用 | 180 MiB |

**压力场景**（576 个物体，全套后处理）：

| 路径 | 帧时间 | CPU | GPU |
|------|--------|-----|-----|
| 逐物体绘制 | 2.50 ms (400 fps) | 2.50 ms | 0.92 ms |
| **GPU 驱动** | **1.19 ms (839 fps)** | 1.19 ms | 0.91 ms |

GPU 驱动把命令录制从 2.07 ms 压到 0.90 ms —— 而这一段此前是整帧的绝对大头。

#### 本周期的性能演进（压力场景，576 物体）

| 阶段 | 帧时间 | 说明 |
|------|--------|------|
| 周期开始 | 3.48 ms | 逐物体绘制，逐 Pass 推送 push constant |
| 相机通道 GPU 驱动 | 2.17 ms | 深度预通道与前向通道走间接绘制 |
| 多视图 GPU 驱动 | 1.03 ms | 三级级联阴影也走间接绘制 |
| 半分辨率 GTAO | — | GTAO 0.70 → 0.29 ms，GPU 整帧降 35% |

**整条链快了 3.4 倍**，而画面逐像素一致（`--gpu-driven-check` 逐次比对，
2,764,800 个通道最大差异 0/255）。

#### 验证体系

这是本项目与多数早期引擎最不一样的地方：**每一条检查都做过变异验证** ——
先把被检查的东西改错，确认它真的会红，再把它接进流水线。判定一律走退出码，
不解析输出文本。

`Scripts/verify.ps1` 现有 **45 个步骤**，全部通过：

| 类别 | 步骤数 | 代表性判据 |
|------|--------|------------|
| 静态检查与构建 | 12 | 零 STL / 零 CRT / 无裸 new-delete；矩阵存储序（uniform 与 push constant 必须 row_major）；C++ 结构体与 SPIR-V 反射逐字段一致；CI 与本地命令逐字等价 |
| 单元测试 | 14 | 749 个用例（Core 406 / Asset 200 / Engine 85 / RHI 58），带用例数下限——防的是"套件悄悄消失" |
| GPU 数值自检 | 14 | 白炉能量守恒；GTAO 朝解析值 0.5 收敛；TAA 与超采样真值比对；分簇与暴力法逐像素等价；三种阴影的边界都落在相似三角形算出的位置 |
| 图像与集成 | 5 | 两份图像回归基线；综合场景"每个子系统都留下痕迹"；交换链重建；资产导入回归 |

**判据的设计原则**：失败模式绝不能落在"通过"上。本周期光是这一类缺陷就抓出
十余个 —— 包括一个报"分配了几块"而不是"画了几块"的计数器（于是"只画第一块"
这条变异满分通过），以及三个套件注册了整整一个周期却一次都没被执行过。
